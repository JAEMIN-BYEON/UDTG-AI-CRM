# 운수대통로지스 상담 AI 시스템 설계서

> 근거 문서: 대표자 기획안 「상담 AI 구축 기획안」 (2026.07)
> 작성일: 2026-07-13 / 버전: v0.1 (초안)

---

## 1. 목적

내방 고객 상담에서 기본 정보 설명에 쓰이는 시간을 제거하고, 고객의 개인정보·희망 조건·관심 브랜드를 기준으로 **보유 물량을 자동 추천**하는 상담 표준화 시스템을 구축한다.

담당자는 AI가 정리한 상담 데이터를 바탕으로 심층 상담·맞춤 컨설팅에 집중한다.

## 2. 범위

### 포함

1. **상담신청서** — 내방 고객이 PC/태블릿에서 직접 입력하는 구조화된 접수 폼
2. **AI 물량 추천** — 입력 조건 기반 보유 물량 매칭 + 추천 사유 생성
3. **클릭형 교육영상** — 추천 결과 항목별 짧은 교육영상 재생 + 시청 이력 기록
4. **담당자 전달** — 상담 요약 리포트(출력용) 자동 생성 및 담당자 알림
5. **관리자 기능** — 물량 DB 관리, 영상 관리, 상담 이력 조회
6. **기록 보존** — 개인정보 동의, 추천 내용, 시청 이력 로그 (법적 리스크 감소)

### 제외

- **선탑 일정 캘린더/확정 워크플로** — 다우오피스 부서별 캘린더로 운영하기로 확정 (2026.07 결정). 본 시스템은 상담신청서의 "선탑 가능 일정" 희망값을 수집해 담당자 리포트에 표기하는 것까지만 담당한다.
- 다우오피스 KPI 자동 집계 — 별도 과제. 본 시스템은 연계 가능한 데이터 구조만 보장한다(§12).

## 3. 용어 및 역할

| 용어 | 정의 |
|---|---|
| 상담자 | 내방한 고객(예비 기사). 상담신청서를 직접 입력하는 주체 |
| 담당자 | 심층 상담을 진행하는 마케팅본부 직원 |
| 운영본부 | 물량(브랜드/코스) 정보의 원천 관리 주체 |
| 물량 | 회사가 보유한 배송 코스/브랜드 단위의 일감 (예: 다이소 상온, 편의점 저온, 쿠팡 간선, 식자재) |
| 관리자 | 물량 DB·영상·계정을 관리하는 시스템 운영자 |

## 4. 전체 흐름

```
고객 방문
  → PC/태블릿 배정 (키오스크 모드 브라우저)
  → 개인정보 수집·이용 동의
  → 상담신청서 작성 (§5 입력 항목)
  → AI 물량 추천 (규칙 매칭 + 추천 사유 생성)
  → 추천 항목별 교육영상 시청 (클릭형, 시청 이력 기록)
  → 최종 상담신청 완료
  → 담당자 알림 + 상담 요약 리포트 생성
  → 리포트 출력 후 심층 상담
  → (선탑 일정: 다우오피스 캘린더에서 진행 — 본 시스템 범위 외)
```

## 5. 상담신청서 입력 항목

기획안 Ⅲ장 기준. `*` = 필수.

**개인정보**: 성명\*, 연락처\*, 거주지역\*, 연령\*, 운전경력, 화물경력, 보유 면허\*, 화물운송종사자격증 여부\*

**희망 조건**: 희망 수입\*, 희망 근무지역\*, 희망 근무시간, 주간/야간 가능 여부\*, 희망 브랜드, 체력 수준\*, 초기 자금\*, 차량 보유 여부\*, 신차/중고차 희망

**상담 신청 내용**: 관심 물량, 궁금한 부분, 선탑 가능 일정, 가족 동의 여부, 특이사항

입력 편의를 위해 주관식은 최소화하고 선택형(버튼/슬라이더) 중심으로 구성한다. 고령 고객을 고려해 큰 글씨·단계별 진행(한 화면 한 주제) UI를 적용한다.

## 6. 데이터 모델

```
users            시스템 사용자 (담당자/운영본부/관리자)
consultations    상담 세션 (고객 1회 방문 = 1건)
listings         물량 마스터 (운영본부 관리)
recommendations  상담 1건에 대한 AI 추천 결과 (물량별)
videos           교육영상 마스터
video_views      시청 이력
consents         개인정보 동의 이력
audit_logs       주요 행위 감사 로그
```

### 6.1 listings (물량 마스터) — 추천 품질의 핵심

| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | uuid PK | |
| brand | text | 브랜드명 (다이소, CU, GS, 쿠팡 간선, 웰스토리 …) |
| category | enum | `상온배송` `저온배송` `간선` `식자재` … |
| region | text[] | 근무 지역 |
| work_hours | text | 근무시간대 (예: 06:00–15:00) |
| shift | enum | `주간` `야간` `격일` |
| pay_structure | enum | `완제` `무제` `매출제` |
| expected_income_min/max | int | 예상 월 실수령 범위 (만원) |
| physical_load | int 1–5 | 상·하차 강도 (5=강함) |
| load_type | text | 롤테이너/박스 등 상하차 방식 |
| number_plate | enum[] | 가능한 넘버 방식: `개별` `법인` `법인임대` |
| vehicle_requirement | text | 차량 톤수/타입 조건 |
| initial_capital_min | int | 최소 초기 자금 (만원) |
| pros / cons | text | 장점 / 단점 |
| sunTop_available | bool | 선탑 가능 여부 |
| is_active | bool | 모집 중 여부 |
| updated_by / updated_at | | 운영본부 갱신 책임 추적 |

### 6.2 consultations (상담)

고객 개인정보 + 희망 조건(§5 전체 필드) + 상태(`작성중` → `추천완료` → `접수완료` → `심층상담완료`), 배정 담당자, 생성/완료 시각. 연락처 등 식별 정보는 암호화 저장(§11).

### 6.3 recommendations

| 컬럼 | 설명 |
|---|---|
| consultation_id / listing_id | FK |
| rank | 추천 순위 (1–3) |
| score | 규칙 매칭 점수 |
| score_breakdown | jsonb — 항목별 득점 근거 (감사 목적) |
| reason_text | LLM 생성 추천 사유 (고객에게 표시된 원문 그대로 보존) |
| model_id | 사유 생성에 사용한 모델 ID (기록 보존) |

### 6.4 videos / video_views

- `videos`: 제목, 주제 태그(`완제무제매출제` `넘버방식` `상하차` `선탑목적` `운송료실수령` `차량조건` `계약절차` `브랜드별장단점` `다이소` `편의점` `쿠팡간선` `식자재`), 파일 URL, 길이, 버전
- `video_views`: consultation_id, video_id, 시작/종료 시각, 완료 여부 — "고객이 무엇을 보고 이해했는지"의 법적 기록

### 6.5 consents

동의 항목(수집·이용/제3자 제공 등), 동의 시각, 동의 문안 버전, consultation_id. 문안 자체를 버전 테이블로 보관해 "당시 어떤 문구에 동의했는지" 재현 가능하게 한다.

## 7. AI 추천 엔진

**원칙: 후보 선정은 규칙이, 설명은 LLM이.** 추천 대상은 항상 물량 DB에 존재하는 실물이어야 하며, LLM은 새로운 물량을 만들어내지 않는다.

### 7.1 1단계 — 하드 필터 (탈락 조건)

- `is_active = false` 제외
- 야간 불가 고객 → `shift = 야간` 제외
- 초기 자금 < `initial_capital_min` → 제외 (단, `법인임대` 넘버 가능 물량은 완화)
- 희망 근무지역과 `region` 불일치 → 제외 (인접 지역은 감점만)

### 7.2 2단계 — 스코어링 (가중치 합산)

| 항목 | 가중치 | 로직 |
|---|---:|---|
| 희망 수입 부합 | 25 | 희망 수입이 `expected_income_min~max` 안이면 만점, 벗어난 정도로 감점 |
| 체력 부합 | 20 | 고객 체력 수준 vs `physical_load` 차이 |
| 근무시간/주야간 | 20 | 희망 시간대와 겹침 정도 |
| 경력 적합 | 15 | 초보자 ↔ 난이도(강도·간선 여부) 매칭 |
| 희망 브랜드 일치 | 10 | 직접 지명 시 가점 |
| 초기 자금 여유 | 10 | 자금 대비 진입 방식(넘버) 부담 |

가중치는 `config` 테이블에 두고 관리자 화면에서 조정 가능하게 한다(코드 배포 없이 튜닝). 상위 3건을 추천으로 확정한다.

기획안의 예시 매핑은 위 규칙의 검증 케이스로 사용한다:

| 고객 조건 | 기대 추천 |
|---|---|
| 50대, 초보, 주간 희망 | 다이소/상온 배송 |
| 30대, 고수입 희망, 체력 좋음 | 식자재/대형/간선 |
| 야간 가능, 안정성 희망 | 편의점 저온 (CU/GS) |
| 체력 부담 있음 | 롤테이너 중심 코스 |
| 초기 자금 부족 | 법인임대넘버 가능 물량 |

### 7.3 3단계 — 추천 사유 생성 (OpenAI API)

확정된 상위 3건에 대해 고객 조건 + 해당 물량의 DB 필드만을 컨텍스트로 주고, 기획안 Ⅳ장의 출력 항목(추천 사유, 근무시간, 운송료 구조, 상·하차 강도, 차량 조건, 장점, 단점, 선탑 가능 여부)을 **구조화 출력(Structured Outputs, JSON schema)** 으로 생성한다.

- 기존 활용 중인 OpenAI API 계정을 그대로 사용한다 (교육영상 대본 제작도 GPT 활용 — 기획안 Ⅴ장 — 이므로 공급자 일원화).
- 모델: 짧은 한국어 사유 생성 용도이므로 경량(mini급) 모델로 충분 — 상담 1건당 호출 1회, 입력 ~2K/출력 ~1K 토큰 수준이라 건당 비용은 수 원 이하. 품질 미달 시에만 상위 모델로 승급.
- 시스템 프롬프트에 "제공된 물량 데이터에 없는 수치·조건을 만들지 말 것"을 명시하고, 생성 결과의 수치 필드는 DB 값을 그대로 바인딩(LLM은 서술 텍스트만 생성)한다.
- API 장애 시 폴백: 규칙 점수 근거(`score_breakdown`)를 템플릿 문장으로 조립해 표시 — 추천 자체는 LLM 없이도 동작해야 한다.

## 8. 클릭형 교육영상

- 추천 결과 화면의 각 용어/항목(완제·무제·매출제, 넘버 방식, 상·하차, 선탑, 운송료·실수령, 차량 조건, 계약 절차, 브랜드별 장단점, 브랜드별 배송 소개)에 ⓘ 버튼 → 모달로 영상 재생.
- 영상 제작 파이프라인(대본 GPT → 음성 일레븐랩스 → 아바타 HeyGen → 편집자)은 시스템 외부 프로세스. 시스템은 업로드·태깅·버전 관리만 담당한다.
- 영상 미제작 주제는 텍스트 카드로 폴백 표시 (1차 오픈을 영상 제작 일정에 종속시키지 않기 위함).
- 재생 시작/종료/완료 이벤트를 `video_views`에 기록.

## 9. 담당자 전달 & 요약 리포트

상담자가 최종 접수를 완료하면:

1. **요약 리포트(A4 1–2장, PDF)** 자동 생성 — 고객 기본정보, 희망 조건, AI 추천 3건과 사유, 시청한 영상 목록, 고객 질문, 선탑 희망 일정, 특이사항, 심층 상담 체크포인트(기획안 Ⅶ장 항목: 추천 적합 이유, 장단점 비교, 실제 근무시간, 예상 실수령 구조, 차량 준비 방향, 넘버 방식, 선탑 확인사항, 계약 가능 여부, 투입 가능 일정)
2. **담당자 알림** — 1차: 시스템 내 대시보드 신규 접수 표시 + 브라우저 알림. 2차(추후): 다우오피스 쪽지/메신저 연동.
3. 담당자는 리포트를 출력해 심층 상담을 진행한다.

## 11. 개인정보 및 보안

- **동의 우선**: 동의 없이는 어떤 입력도 저장하지 않는다 (K1 → K2 순서 강제).
- **암호화**: 연락처 등 식별자는 컬럼 암호화(AES-256), 전송 구간 TLS.
- **접근 통제**: §3 권한 매트릭스 기반 RBAC. 고객 키오스크 세션은 접수 완료/타임아웃 시 즉시 파기.
- **보관 기간**: 상담 데이터 보관 기간 정책(예: 계약 미체결 고객 1년 후 파기 또는 비식별화)을 설정 화면에서 관리. 파기 배치 작업 포함.
- **감사 로그**: 개인정보 열람·출력·수정 행위를 `audit_logs`에 기록.
- LLM 호출 시 성명·연락처는 컨텍스트에서 제외(추천에 불필요) — 연령·경력·조건만 전달.

## 12. 다우오피스 연계 (후속 단계)

- 상담 데이터의 용어·필드를 다우오피스 고객관리 필드와 사전에 매핑해 설계한다(용어 통일 — 7.6 대표자 회의 결정 사항 반영).
- 1차: 담당자가 리포트 기준으로 다우오피스에 수기 등록.
- 2차: 접수 완료 시 CSV/API로 다우오피스 고객관리에 자동 등록 → "DB유입 → 내방상담 → 선탑전환 → 계약" KPI 집계 파이프라인에 연결.
- 선탑 일정은 다우오피스 캘린더에서 진행하므로, 리포트에 "선탑 희망 일정" 표기까지만 책임진다.

## 15. 리스크 및 결정 필요 사항

1. **물량 DB 최신성** (최대 리스크): 운영본부의 갱신 책임자·주기를 대표 승인으로 확정해야 함. 갱신 지연 시 추천 품질이 직접 훼손됨. → 물량별 `updated_at` 30일 초과 시 관리자 경고 표시로 보완.
2. **영상 제작 일정**: 시스템과 병렬 진행, 텍스트 폴백으로 오픈 차단 요소 제거.
3. **개인정보 보관 기간 정책**: 법무 검토 후 수치 확정 필요.
4. **키오스크 기기**: 매장 PC 재활용 vs 태블릿 구매 — 예산 결정 필요.
